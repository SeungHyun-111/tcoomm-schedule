## 저장 즉시 화면 반영·페이지/권한별 도움말·이름 표시

| 작업 | 파일 |

- 저장 응답에 실제 커밋된 원본 행의 변경값과 이전/새 버전을 포함합니다. 클라이언트는 이전 버전이 맞는 공통 캐시만 불변 복사로 갱신한 뒤 화면을 다시 계산하고 서버 버전을 확인합니다. 변경된 권한의 캐시에는 쓰지 않습니다. 브랜드명 변경 시 선택한 브랜드의 상세 조회 상태도 함께 변경합니다. 다른 메뉴를 다녀올 필요가 없습니다.
- 우상단 도움말 버튼은 월간·주간·전체목록·권한관리·접속/변경로그 각각의 코치마크를 엽니다. 일반 뷰어에게는 조회와 수량 안내, 매출 권한에게는 매출 조회, 관리자에게는 수정·일괄 변경·권한 관리 기능을 안내합니다. 관리자 페이지는 관리자만 접근할 수 있습니다. 코치마크를 닫으면 도움말 버튼으로 초점을 돌려주며, Esc로 닫을 수 있습니다. 화면 크기·스크롤·지연 로딩에 맞춰 위치를 다시 계산합니다.
- 이름과 이메일, `일반 뷰어`/`매출 권한`/`관리자` 배지를 상단에 표시합니다. 이름은 People API 조직 디렉터리에서 접속 이메일과 정확히 일치하는 프로필만 사용합니다. 배포 실행자 이름을 다른 접속자에게 표시하지 않습니다. 이름 조회는 별도 호출이며 실패 시 이메일을 표시합니다. 성공한 이름은 서버 캐시에 최대 6시간 보관합니다.
- `appsscript.json`에 People v1 고급 서비스와 `directory.readonly` 범위를 추가했습니다. 새 권한 승인이 필요할 수 있습니다. 기본 Apps Script Cloud 프로젝트는 고급 서비스 추가 시 해당 API가 활성화되며, 별도 표준 Cloud 프로젝트를 사용한다면 People API 활성화가 필요합니다. 조직 디렉터리 공개 설정에 따라 이름을 조회하지 못할 수 있습니다. 참고: [People 조직 디렉터리 검색](https://developers.google.com/people/api/rest/v1/people/searchDirectoryPeople), [Apps Script 고급 서비스](https://developers.google.com/apps-script/guides/services/advanced).
- 검증: 로컬 빌드와 서버 모킹 30개, Edge에서 3개 역할별 페이지 도움말 및 제자리 브랜드 변경을 확인했습니다. 실제 회사 Google 계정의 디렉터리 조회/재배포 및 운영 RTDB 쓰기는 수행하지 않았습니다.

## 저장 진행 추적·검색 인덱스 증분 수정·월간 브랜드 수정

| 작업 | 파일 |
| --- | --- |
| 스크립트 추가 | `SaveProgress.gs`, `EditSearchIndex.gs` |
| 기존 서버 내용 교체 | `DataEdits.gs` |
| 기존 HTML 내용 교체 | `Scripts.html`, `Scripts2.html`, `Scripts3.html`, `Scripts4.html`, `Scripts5.html` |
| 기존 스타일 내용 교체 | `Styles.html` |

- 저장하는 동안만 4초 간격으로 진행 상태를 조회합니다. 일반 데이터 조회의 자동 폴링은 추가하지 않습니다. 브라우저 콘솔의 `[MSM SAVE 작업번호]`에는 총 경과 시간, 마지막 서버 단계, 단계 대기 시간, 서버 상태 갱신 시각이 나옵니다. GAS 실행 로그에도 동일한 작업번호를 남깁니다. 진행 캐시는 10분간 보관하고 요청한 관리자만 조회할 수 있습니다. 캐시 누락이나 GAS 요청 대기 때문에 상태 조회가 지연될 수 있으므로 마지막 확인 단계는 중단 확정 판정이 아닙니다.
- 단계: `server-start`, `lock-wait`, `token`, `source-read`, `validate-rows`, `journal-write`, `source-write`, `index-build`, `index-delta-ready`, `index-sync`, `completed` 또는 오류 상태. 인덱스 버전 불일치 시 `index-rebuild`로 전체 복구가 표시됩니다. `[MSM RPC]`는 저장 후 재조회 등 각 API의 요청/응답 시간을 구분합니다.
- 기존에는 한 셀만 수정해도 월 전체 검색 인덱스를 재생성한 뒤 잠금을 해제했습니다. 이제 정상 v2 인덱스는 변경된 문서의 브랜드/상품 검색어 차이만 반영합니다. MD분류·가격 등 검색어에 포함되지 않는 필드 변경은 검색어 재생성을 하지 않습니다. 인덱스가 누락되거나 버전이 다르면 안전하게 전체 복구합니다. 원본·검색 인덱스 동기화 완료까지 동시 수정 잠금과 ETag 검사는 유지합니다.
- 월간 대시보드에서 관리자가 브랜드 셀을 우클릭하면 브랜드명·카테고리를 수정합니다. 변경 범위는 선택 월·회사·브랜드 및 현재 MD분류 필터에 포함된 원본 행으로 고정하며, 필터가 전체면 모든 MD분류가 포함됩니다. 원본 행 번호를 유지해 다른 카테고리의 동명 브랜드를 변경하지 않습니다. 저장 시 기존 변경 이력에 기록합니다.
- 검증은 로컬 빌드, 서버 모킹 29개와 역할별 Edge 화면 검사입니다. 동명 브랜드의 다른 MD분류 제외, 지연 저장 중 진행 조회, 직접 셀 수정·취소를 확인했습니다. 실제 GAS 실행과 운영 RTDB 쓰기/시간 측정은 수행하지 않았습니다.

## 초기 로딩·공통 캐시 개선

이번 수정은 기존 GAS 프로젝트에서 아래 파일 내용을 교체한 뒤 새 버전으로 재배포합니다. 추가할 GAS 파일은 없습니다.

| 작업 | 파일 |
| --- | --- |
| 서버 파일 교체 | `Code.gs`, `Dashboard.gs`, `Competitor.gs` |
| HTML 교체 | `Index.html`, `Scripts.html`, `Scripts2.html`, `Scripts3.html`, `Scripts4.html`, `Scripts5.html` |

- 첫 HTML에는 월간 스크립트/스타일만 포함합니다. 다른 화면의 스크립트/스타일은 해당 메뉴 최초 진입 시 서버에서 가져오며, 이후 같은 탭에서는 재사용합니다. 초기 스크립트 약 1.44MB → 0.31MB이며 전체 번들 자체의 React 중복 제거는 이번 범위에 포함하지 않습니다. 주간 화면 등은 첫 진입 때 자산 요청 한 번이 필요합니다.
- 권한 관리/로그 자산 조회도 서버에서 관리자 권한을 검사합니다. 기존 데이터 API의 권한 검사와 매출 제거는 유지합니다.
- IndexedDB 연결 직후 공통 캐시를 먼저 읽고, 권한이 다른 캐시 정리는 뒤에서 키만 조회합니다. 저장 후 최대 6개월 정리도 전체 월별 payload를 역직렬화하지 않습니다. 디스크에서 읽은 원본을 다시 저장하는 작업을 줄였습니다.
- 캐시가 없는 월은 원본을 바로 조회합니다. 버전 확인이 필요한 월은 updatedAt을 조회하며, 독립적인 월 요청은 fetchAll로 병렬 처리합니다. 클라이언트 권한 구분값이 다르면 원본을 새로 받는 보안 동작은 유지합니다.
- 허용 접속 로그는 HTML 반환을 막지 않고 초기 계정 확인 후 별도 서버 호출로 기록합니다. 페이지가 실행되기 전에 닫히거나 해당 호출이 실패하면 허용 로그가 누락될 수 있습니다. 거부 접속은 기존처럼 서버에서 즉시 기록합니다.
- 주기적인 폴링은 추가하지 않습니다. 메뉴 이동·포커스 복귀 등의 기존 갱신 확인 방식을 유지합니다.

검증: 로컬 빌드, 서버 모킹 26개 검사, Edge에서 지연 자산 로딩 및 viewer/revenue/admin 역할별 조회·수정·권한 변경 화면 검증을 통과했습니다. 회사 GAS 재배포 및 실제 RTDB 성능 측정은 수행하지 않았습니다.

### 권한

- 일반 뷰어: 별도 등록 없음. 월간·주간·전체 목록 조회. 매출액/분당 매출액 헤더·열·합계·툴팁은 표시하지 않습니다. 서버도 매출과 임의 금액 필드를 제거한 허용 필드만 응답합니다.
- 매출 권한: 매출액 조회 가능. 권한 관리·접속/변경 로그·원본 수정은 불가.
- 관리자: 매출 조회 및 권한 관리·접속/변경 로그·원본 수정 가능. `l.sh@skstoa.com`은 고정 초기 관리자입니다.
- 권한 관리 페이지에서 회사 이메일에 매출/관리자 권한을 지정하거나 일반 뷰어로 돌릴 수 있습니다. 권한 저장 기준은 기존 GAS 서버 속성이며 RTDB는 명부/이력 사본입니다.
- 데이터 조회 API는 서버 역할과 캐시 권한 식별자를 함께 확인합니다. IndexedDB는 `msm-gas-months-v2-scoped`로 분리하고 사용자·권한별로 키를 구분합니다. 구형 캐시는 읽지 않으며, 권한 변경 시 메모리와 이전 권한의 디스크 레코드를 정리합니다. 이미 과거에 전달·다운로드한 자료를 소급 회수할 수는 없습니다. 다른 기존 앱/RTDB 직접 접근 정책은 이 앱의 권한과 별개이며 이 작업에서 변경하지 않습니다.
- 권한 변화는 다음 서버 권한 검증/재접속 때 감지합니다. 화면을 보고 있는 동안 주기적으로 권한을 확인하는 폴링은 없습니다.
- 일반 뷰어의 주간 블록과 상세 툴팁은 판매가격·판매수량을 표시합니다. 전체 목록의 판매수량 헤더/셀과 주간 툴팁에는 `페이지 소스의 방송시작 재고수량 - 방송종료 재고수량` 설명을 둡니다.

### 관리자 데이터 수정

전체 목록에 관리자만 보는 `브랜드명 일괄 수정` 버튼과 행별 `수정` 버튼을 추가했습니다. 별도 컴포넌트 `src/components/DataEditModal.jsx`, 서버 `DataEdits.gs`로 분리했습니다.

- 일괄 변경은 현재 조회 기간·선택 회사 전체를 대상으로 합니다(검색/열 필터로 현재 보이는 일부 행만을 뜻하지 않음). 기존 브랜드명을 검색/선택하고, 변경 브랜드명을 기존 이름에서 선택하거나 새로 입력합니다. 저장 전 대상 건수를 표시합니다.
- 행 수정은 14개 원본 필드에 적용합니다. 날짜는 원본 월 안에서만 수정하며 다른 월로 방송을 이동하지 않습니다. 원본 C열 weightedMin과 N열 brandWeightedMin은 별개이며, 이 표의 가중분은 N열을 수정합니다. 원본 시트의 계산식을 재실행하지 않습니다.
- `RTDB에 저장`을 누르면 승인 대기 없이 같은 DB에 저장합니다. 조회 시점 updatedAt이 달라졌거나 REST ETag/If-Match 조건부 저장이 412로 거부되면 덮어쓰지 않습니다. 한 번에 최대 5,000행입니다.
- 월별 원본 저장 후 검색 인덱스·메타데이터·updatedAt을 갱신하고 화면 캐시를 무효화합니다. 변경 전·후 값과 변경자는 `changeLogs/tcoomm/days/{한국날짜}/{UUID}`에 기록합니다.
- 변경 이력은 원본 쓰기 전에 pending으로 남깁니다. 적용 완료/미적용/인덱스 동기화 확인 필요 상태를 구분합니다. 여러 월을 수정하면 월 단위로 저장하므로 일부 월만 적용될 수 있으며 결과 건수/오류를 화면에 표시합니다. 인덱스 동기화 실패를 자동 재시도하는 별도 작업자는 포함하지 않습니다.
- **RTDB 직접 수정입니다. 기존 MSM/PGMDR에서 원본 Google Sheets를 다시 가져와 월 원본을 교체하면 수동 수정이 덮어써질 수 있습니다.** 원본 시트 수정이나 외부 갱신기의 정정 재적용 기능은 구현하지 않았습니다.

접속 로그 페이지 아래에 변경 로그 목록/상세를 추가했습니다. 위 날짜·이메일(변경자) 필터를 사용하며, 수정 전후 값은 관리자만 조회합니다.

### RTDB 갱신 서버 API 설정

편성표 조회에는 추가 설정이 필요 없습니다. 현재 원본 갱신 버튼은 화면에서 제거되어 있습니다. 보존된 서버 갱신 API를 사용할 때는 스크립트 속성에 다음을 설정합니다.

## 사용 순서

1. 이 폴더의 `gas/`에 있는 `.gs`, `.html` 파일을 **동일한 Apps Script 프로젝트**에 이름대로 만듭니다. 편집기에서 `.gs`와 `.html` 확장자는 자동으로 붙습니다. 기본 Code.gs 내용은 이 폴더의 Code.gs로 교체합니다. 서로 다른 GAS 프로젝트에 나누지 마세요.
2. GAS 프로젝트 설정에서 `appsscript.json 매니페스트 파일 표시`를 켜고 이 폴더의 매니페스트 내용으로 설정합니다.
3. 기본 허용 도메인은 `skstoa.com`입니다. 변경할 때 프로젝트 설정 → 스크립트 속성에 `ALLOWED_DOMAIN`을 등록합니다. 특정 사람만 허용하려면 `ALLOWED_EMAILS`를 쉼표 구분 이메일로 등록합니다. 비워 두면 회사 도메인 사용자를 허용합니다.
4. RTDB 읽기 인증을 설정합니다. 기본은 GAS 실행 계정의 OAuth 토큰이며, 실행 계정이 `schedule-7ec7a`의 RTDB 조회 IAM 권한을 가져야 합니다. 기존 DB가 공개여도 이 앱은 인증을 붙여 요청합니다. HTTP 401/403이면 실행 계정의 Firebase IAM 권한을 확인하거나 다음 서비스 계정 방식을 사용하세요.
5. 서비스 계정을 쓸 경우 Firebase 프로젝트에서 RTDB 조회 권한을 가진 서비스 계정 키 JSON 전체를 **스크립트 속성** `FIREBASE_SERVICE_ACCOUNT_JSON` 값에 넣습니다. 파일·React 코드·채팅에 키를 넣지 않습니다. 앱은 서버에서 단기 OAuth 토큰을 발급합니다. 이 속성은 GAS 프로젝트 편집자에게 노출되므로 프로젝트 편집 권한은 필요한 사람에게만 줍니다.
6. 배포 → 새 배포 → 웹 앱: 실행 사용자는 **본인**, 접근 권한은 **회사 도메인 사용자**로 설정하고 배포합니다. 발급받은 `/exec` URL을 사용합니다.
7. 본인 회사 계정으로 데이터 조회, 다른 회사 계정으로 접속, 개인 계정 차단만 확인합니다. 이메일 식별이 빈 값이면 안전하게 차단되며 실제 배포의 사용자 식별 설정을 조정해야 합니다.

기존 RTDB 규칙을 자동 변경하지 않습니다. 이 앱이 보호되어도 다른 클라이언트의 DB 접근 규칙은 별개입니다.

## 로컬 수정 후 다시 빌드

```powershell
cd D:\CODEX\웹페이지_프로젝트\T-coomm편성\gas-msm-dashboard
npm install
npm run build
```

현재 작업 공간에서는 기존 draft-schedule의 설치된 React/Vite/dayjs를 재사용해 `node scripts/build.mjs`로도 빌드할 수 있습니다. 월간 화면 변경은 Styles.html/Scripts.html, 주간 화면 변경은 Styles2.html/Scripts2.html에 반영됩니다. 서버 코드도 수정했다면 해당 .gs 파일을 함께 교체합니다. 웹앱 배포는 새 버전으로 갱신해야 합니다.

## clasp로 업로드할 경우

`.clasp.example.json`을 `.clasp.json`으로 복사하고 `scriptId`에 만든 GAS 프로젝트의 스크립트 ID를 입력합니다. 배포 ID가 아닙니다.

```powershell
npx clasp login
npm run build
npx clasp push
```

필요하면 Google Apps Script 사용자 설정에서 Apps Script API를 켭니다. `clasp push`는 대상 프로젝트의 파일을 동기화하므로 이 대시보드 전용 프로젝트를 사용하세요. 업로드 후 GAS에서 배포 → 배포 관리 → 수정 → 새 버전으로 갱신합니다. 이 작업에서는 로그인·업로드·배포를 수행하지 않았습니다.

## 필요한 검증

`npm run check`는 인증·캐시 버전·같은 월 경로 조회·갱신 권한·원자적 갱신·조회 주차 경로를 모킹으로 확인합니다. `node scripts/check-weekly.mjs`는 기존 PGMDR의 Playwright와 설치된 Edge로 Urban 편성표·월간 캐시 공유·CA/IP·자정 연속·검색 집계·요약·채널 전환을 확인합니다. 운영 DB에는 요청하지 않습니다. 실제 회사 계정 접속·RTDB 권한·iframe 브라우저 저장은 GAS 배포 후 확인해야 합니다.

React·CSS는 HTML 안에 포함되며 외부 CDN이나 Firebase 브라우저 SDK를 사용하지 않습니다. 화면이 받은 데이터와 JavaScript는 접속 사용자에게 보입니다. 월 선택/화면 상태는 localStorage에, 월별 원본은 사용자별 IndexedDB에 최대 6개월 저장합니다.

## 월별 원본 캐시

- 최초 접속에서는 bootstrap으로 회사 계정·조회 권한을 확인합니다. 이후 30초 이내에 확인한 월은 공통 메모리 캐시에서 즉시 재사용하고 GAS 데이터 요청을 생략합니다. 30초가 지나면 서버에서 사용자 권한과 `competitorInfo/monthly/{YYYYMM}/updatedAt`을 다시 확인합니다.
- 월간/주간 독립 번들은 `window.__MSM_MONTH_CACHE__`를 통해 메모리·버전 확인 시각·IndexedDB 연결까지 공유합니다. 재검증이 필요해도 캐시가 있으면 먼저 표시하고 변경된 원본만 뒤에서 교체합니다. 변경 확인은 화면 조회 시 수행하며 자동 실시간 구독은 없습니다. 상단 다시 조회 버튼은 제거했습니다. 메뉴 전환·월/주차/채널 변경·재접속·브라우저 탭 복귀 시에만 확인하며 주기적 폴링은 하지 않습니다. 검색·마우스 이동 등 일반 React 렌더링은 요청을 발생시키지 않습니다.
- 월간 화면은 주간 화면으로 이동해도 숨긴 상태로 유지해 돌아올 때 재생성·재계산을 줄입니다. 메모리 캐시 조회는 대용량 디스크 쓰기를 기다리지 않으며, 원본 저장·보관 개수 정리는 화면 표시와 분리해 뒤에서 수행합니다.
- 브라우저 원본과 버전이 같으면 원본을 전송하지 않고 캐시를 재사용합니다. 버전이 다르거나 캐시가 없으면 해당 월만 다운로드합니다. 갱신 시 원본의 updatedAt을 반드시 함께 변경해야 합니다.
- 별도 metadata 경로 대신 원본 안의 updatedAt을 사용하여 MSM의 메타데이터 저장 지연/실패에 영향을 받지 않습니다. 타임스탬프가 없으면 안전하게 원본을 매번 읽고 캐시하지 않습니다.
- IndexedDB `msm-gas-months-v1`에 이메일/월별로 저장하며 최근 조회 순으로 사용자마다 최대 6개월 유지합니다. 브라우저 저장이 차단되거나 실패하면 메모리 캐시로 동작합니다. 저장소가 브라우저에서 삭제되거나 GAS iframe 저장 영역이 바뀌면 다시 다운로드합니다.
- 재검증 중에는 저장된 화면을 표시하며, 서버 요청이 실패하면 해당 화면의 캐시 표시를 중단하고 오류를 보여줍니다. 캐시는 사용자 PC에 남는 업무 데이터이므로 공유 PC에서는 브라우저 사이트 데이터를 삭제하면 됩니다.
- 콘솔 `[MSM CACHE]`에 즉시 표시/서버 요청 생략 여부, 재사용/새 다운로드 개수, 소요 시간을 표시하며 원본 내용은 로그에 남기지 않습니다. 캐시는 사용자별 PC에 존재하며 사용자 간 다운로드를 공유하는 서버 캐시는 아닙니다.

`node scripts/check-ui.mjs`는 기존 PGMDR의 Playwright와 설치된 Edge를 사용해 서버를 모킹한 상태에서 캐시 재사용·갱신·사용자 분리·보관 개수·저장 차단을 확인합니다. 두 화면은 이메일/월별 캐시 키와 IndexedDB를 공유합니다. 처음 보는 월은 3사 월 원본을 받아 보관하고, 이후 주차·채널 전환이나 전주 비교에서는 버전이 같으면 재다운로드하지 않습니다.

## 오류 진단 버전 적용

GAS에 HTML 파일 `Diagnostics`를 추가해 `gas/Diagnostics.html`을 붙여넣고, `Code.gs`, `Index.html`, `Scripts.html`을 최신 파일 내용으로 교체합니다. 새 버전으로 재배포합니다. 콘솔에는 `[MSM STAGE]` 실행 단계와 `[MSM ERROR]` 메시지·파일명·줄·열·스택·주변 코드가 출력됩니다. 브라우저가 동적 스크립트 파일명을 제공하지 않는 경우에는 원래 파일명과 실행 중 번들 기준 소스 후보임을 함께 표시합니다. React 렌더링 오류와 GAS API 실패도 기록합니다. 데이터 응답과 인증 토큰은 기록하지 않습니다.

배포 빌드는 코드를 압축하고 소스맵을 제외합니다. 원본 JSX는 로컬 src/에서 관리합니다. 콘솔 진단은 유지되며, 압축된 번들의 줄/열과 실행 단계·API 실패를 기록합니다. 전체 진단은 `window.__MSM_DIAGNOSTICS__.reports`로 확인할 수 있습니다. 원본 JSX 위치로 자동 역추적하는 소스맵은 포함하지 않습니다.
